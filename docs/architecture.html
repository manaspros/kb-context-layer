Architecture · Multi-document context layer

KB context layer

Some answers need evidence from at least two documents. Standard top-k RAG ranks by similarity to the question, but the hop-2 document is about a bridge entity that only appears after reading hop 1, so it is missed. The RRF top-10 holds every gold document for only 25% of questions, and 2% at 4 hops.

RRF baseline vs this design

  • Exact match .195 → .383 (paired delta +.188, 95% CI [+.145, +.230])
  • All gold docs in context .250 → .475 (delta +.225, CI [+.182, +.270])
  • Cited ≥2 gold docs .370 → .560 (delta +.190, CI [+.140, +.240])
  • LLM calls per question 1.00 → 2.66 (the cost of the loop)

Why this design
  • Sentence spans with stable ids (doc:para:sent): every claim can point at text the model actually read.
  • BM25 + dense + RRF: lexical and semantic recall in one cheap seed set.
  • Title/alias entity graph: links paragraphs to the documents they mention, so bridge entities are addressable.
  • Sufficiency check with a facts ledger: the model states what it already knows and names the next bridge entity, instead of guessing from the question.
  • Bridge hop, up to 2: look the entity up by title first, else search; this is where the measured gain comes from.
  • Fixed 10-paragraph budget, max 2 per document: same budget as the baseline, so one article cannot crowd out the chain; ordered by hop.
  • Cited answer or NOT ANSWERABLE: abstention is an allowed output.
Provenance record

Every answer is stored as a chain, so any claim can be traced back to where it was found.

  • answer → claim (one fact in the answer)
  • claim → span id (doc:para:sent) + verbatim quote
  • span → paragraph → document
  • paragraph → the hop that retrieved it (seed, or bridge hop 1 or 2)

Evaluation setup
  • MuSiQue-Ans dev, all paragraphs pooled into one knowledge base.
  • 400-question seeded, stratified subset by hop count (150 two-hop, 150 three-hop, 100 four-hop).
  • A disjoint 200-question tune split was used for settings; results are on the eval subset only.
  • Same model (deepseek/deepseek-v4.1-flash-1017), prompt and 10-paragraph budget for every system.
  • Paired bootstrap for deltas; the graph ablation runs on a 267-question subset.
