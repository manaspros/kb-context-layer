# EVAL

Everything here is regenerated by `python -m kb eval` from the committed raw outputs; the full generated tables are in
[results/summary.md](results/summary.md) (machine-readable: [results/summary.json](results/summary.json)). If a number
in this file differs from `results/summary.md`, the generated file wins. Tables below are copied from it verbatim.

## 1. Benchmark

- **MuSiQue-Ans v1.0, dev split** (`musique_ans_v1.0_dev.jsonl`, sha256 `15fa63794d18a94ce12411aca6e2327e65b6e83b0b1490efab3f1962e48abf3b`),
  from the Hugging Face dataset `dgslibisey/MuSiQue`, **revision `c8f4f8c9465fb69d31a8eae894c3fd509c4ca321`**. License: CC BY 4.0.
  `kb data` downloads that pinned revision and refuses to continue on a hash mismatch.
- 2,417 questions (2-hop 1,252; 3-hop 760; 4-hop 405). Each carries gold supporting paragraphs and a question decomposition.
- **Why MuSiQue** (full comparison in OPTIONS.md §1): it is built to defeat single-hop shortcuts and has gold supporting paragraphs
  per step. HotpotQA has many questions solvable from one paragraph and heavy contamination; 2WikiMultiHopQA is templated and
  shortcut-prone; MultiHop-RAG has snippet-level evidence only (no sentence locations); FRAMES has document-level labels and needs full
  Wikipedia fetches; BrowseComp-Plus is so hard that baselines sit near the floor at our budget; ALCE defines citation metrics but is not
  multi-hop. No public text benchmark we found has both multi-document gold evidence and claim-level citation labels, so we compose
  MuSiQue with ALCE-style NLI citation metrics.
- **Known weakness:** Wikipedia-derived, so models have seen much of it. The closed-book baseline measures this directly (section 5).

## 2. Corpus and subset

- **Corpus:** every unique (title, paragraph) in the dev set, pooled into one knowledge base for all questions: **21,100 paragraphs in
  17,629 documents** (a document is a Wikipedia title; paragraphs are its sections), split into **72,934 sentence spans**. This is
  a real retrieval problem with cross-question distractors, but it is not full Wikipedia, so absolute numbers are not comparable to
  published full-corpus results.
- **Multi-document filter:** 54 questions whose gold paragraphs all sit under a single title are excluded as not multi-document
  (53 of the 2-hop, 1 of the 3-hop), leaving 2,363. In the 400-question subset the mean is 2.84 gold documents per question
  (2 docs: 160 questions, 3: 145, 4: 95).
- **Eval subset (400):** `random.Random(1337)`, sampled from the sorted ids of each hop stratum: 150 two-hop, 150 three-hop, 100 four-hop
  (4-hop is over-represented relative to its 17% share of the dev set so that it has a usable n). `data/subset_ids.txt`,
  sha256 `cd3ad5e2ce56bb220a3d80484bb4ff44eced4e0584dc234aed6d42918cf54637` (checked by `kb data` and `kb eval`). 400 was sized to the
  token budget; no power analysis was done.
- **Tune split (200):** `random.Random(7)`, 80/70/50 per hop, drawn from questions **outside** the eval subset (asserted
  disjoint). Every hyperparameter was chosen here: graph seed count (7), lookup threshold (0.7), hop cap (2), per-document cap (2), and
  `max_tokens` (8000, on a 68-question slice). `data/tune_ids.txt`, sha256 `cb74c6eae7554c6ab8b80b88aac4439110135afcabc413db01022f40626632bc`.
  One exception: the first seed-count pick (7) was made on the eval set; the tune split later confirmed it (all-gold@10 for 3/5/7/9 seeds:
  0.200/0.215/0.220/0.200 vs RRF 0.145).
- **Unanswerable probe (60):** `random.Random(11)`, 20 per hop, outside eval and tune; every paragraph of the document that supports the
  last decomposition step is masked at query time (325 paragraphs), so the correct output is NOT ANSWERABLE. A check asserts that no
  masked paragraph reaches any context. `data/unanswerable.jsonl`, sha256 `22908728061cc1ee59424a1fabc835364a669f46a5286014183e4cac6032bbcb`.

## 3. Systems, baselines, fairness

| system | what it is |
|---|---|
| closed-book | no evidence; the model answers from memory (measures contamination) |
| BM25 | `bm25s` over `title. paragraph`, English stopwords, no stemmer; top-10 paragraphs |
| dense | `BAAI/bge-small-en-v1.5` with its query prefix; top-10 paragraphs |
| RRF | reciprocal rank fusion of BM25 and dense (k=60, depth 100); top-10. The strongest single-shot baseline |
| **kb** | graph-expanded RRF, then up to 2 gated bridge hops (entity-first lookup, else search), per-document cap 2, final 10 paragraphs |
| kb, no hops / no entity lookup / no graph | ablations of kb |

**Fairness controls.** Same generator for every system: `deepseek/deepseek-v4.1-flash-1017` (open weights), reached through any
OpenAI-compatible endpoint, temperature 0, `max_tokens` 8000. Same answer prompt (one constant in `kb/answer.py`), same
10-paragraph context budget, same corpus and index, same questions, same scorer. **Not equal:** kb spends extra LLM calls on the
sufficiency checks (2.7 calls and 9.9k tokens per question vs 1 call and 3.1k for RRF). We did not run an equal-token baseline, so we cannot
say how much of the gain is "more tokens read" rather than "better evidence". Published numbers (HippoRAG 2 F1 48.6 on MuSiQue, BM25 28.8,
GraphRAG 38.5; OPTIONS.md §4-5) are context only: different corpus, embedder and generator. They are not head-to-head rows.

## 4. Metrics and why

| metric | definition | why |
|---|---|---|
| EM, F1 | official MuSiQue / SQuAD normalisation, best over the gold answer and its aliases | deterministic, no judge model; standard for the benchmark |
| all-gold-in-context | every gold document has at least one paragraph in the final 10 | the coverage metric: the thing the context layer controls |
| gold-doc recall | share of gold documents in the context | partial coverage |
| cited >= 2 gold docs | share of questions where the claims' valid cited spans fall in at least 2 distinct gold documents (answer correctness not required) | the multi-document requirement, measured on citations rather than on retrieval |
| answered rate, EM when answered | NOT ANSWERABLE and unparseable outputs count as unanswered | separates "wrong" from "abstained"; closed-book and RAG abstain at different rates |
| failure stage | wrong = EM 0 and F1 < 0.5; then retrieval_miss (no gold doc in the first retrieval), hop_miss (gold doc never entered the pool), assembly_drop (in the pool, cut from the final 10), generation_wrong; correct answers with no gold document cited are `correct_citation_gap` | attributes each loss to one stage from gold labels |
| span ids valid / quote verbatim | per claim, mechanical: the cited id is in the context; the quote is a substring of a cited span | provenance that can be checked by lookup |
| NLI citation recall / precision / unsupported | local MiniCheck-RoBERTa-Large; premise = cited spans' text, hypothesis = claim; supported if P >= 0.5. ALCE definitions (kb/verify.py): recall = supported claims / claims; precision = relevant citations / citations; unsupported = 1 - recall | claim-level grounding without spending LLM tokens or using a judge from the generator's family |
| tokens, calls per question | from the usage field of each response | cost; dollars depend on the provider's price, so we report tokens |

**Statistics:** paired bootstrap over questions, 10,000 resamples, `numpy.random.default_rng(0)`, 95% percentile interval of the
mean difference. n is always reported. The interval covers question sampling only, not LLM or provider nondeterminism (each system
was run once; temperature 0 does not guarantee identical outputs).

**Eyeball check of the verifier** (`results/verify/audit.jsonl`; 20 random + 12 flagged judgments, read against the cited span text by
the model that wrote this report, not by a human, so treat it as a sanity check and re-read the file):
- 20 randomly sampled judgments across all systems: **19 of 20 agree** (95%). The one disagreement: "born in Mexico, in North America" was flagged
  unsupported because the span says "Guadalajara, Jalisco, Mexico".
- 12 randomly sampled claims the verifier flagged as unsupported: 1 undecidable from the span, and of the other 11, **6 are really unsupported by the cited
  span alone (55%)**. The 5 false flags: a time range ("between 5am and 1am") read against "starting at 5am", a cast list, diacritics ("Da Nang" vs "Đà Nẵng"), a comparison across numbers in one sentence ("the most among the teams listed"), and a restated statistic. Most of the 6 real ones are
  pronoun or ellipsis sentences ("It is part of the City University of New York") whose subject is in the document title, not in the span. So the unsupported rate is
  an upper bound on true ungrounded claims, and the verifier is conservative.

## 6. Failure analysis: four real questions

Each is reproducible with `python -m kb show <id> [--system S]` (no LLM call).

**A. Multi-document success, 2-hop: `2hop__265989_531490`** "Who is the mother of the screenwriter of WarGames?" (gold: Jane Greer). RRF top-10 contains WarGames but not
Lawrence Lasker, and abstains. kb's hop-0 check says "not sufficient; WarGames was written by Lawrence Lasker and Walter F. Parkes", resolves the title `Lawrence Lasker` (lookup path) and pulls his document. Answer
"Jane Greer", with two claims citing two documents: `WarGames — paragraph 0, sentence 0` (found at hop 0) and `Lawrence Lasker — paragraph 0, sentence 1: "He is the son of actress Jane Greer and producer Edward Lasker."` (found at hop 1).
A 3-hop variant, `3hop1__136016_87694_64412` (gold 11 February 1929), chains Leeds Minster, then St. Peter's Basilica (hop 1, lookup), then Vatican City (hop 2, lookup), citing all three gold documents.

**B. hop_miss, wrong bridge, 3-hop: `3hop1__136016_87694_124169`** "On what date did Governor of the location where the basilica named after the same saint as Leeds Minster and the head of the catholic religion end?" (gold 1952). The first
retrieval finds Leeds Minster; hop 1 searches for Vatican City and pulls in `Governor of Vatican City`, but the `St. Peter's Basilica` document never enters the pool; hop 2 then searches "Camillo Serafini: exact date of death" and
returns unrelated paragraphs. kb answers "22 February 2001", the date the 2000 Fundamental Law entered into force. The NLI verifier gives the claim built on that span P=0.37 (unsupported), so the verifier would have flagged this one,
but nothing in `kb ask` acts on it yet.

**C. Unanswerable-probe failure: `3hop1__163024_443779_52195`, `--system kb_unans`** "Who is the president of the newly declared independent country that has a Commission of Truth and Friendship with the country where Ambelau is located?"
The document that supports the last step (East Timor) is masked. RRF abstains. kb finds Ambelau, then the Indonesia-Timor Leste commission, searches "East Timor: Who is the president of East Timor?" and answers
"José Ramos-Horta", citing `Estanislau da Silva — paragraph 0, sentence 2: "He was sworn in as the acting Prime Minister on 19 May 2007 to replace José Ramos-Horta who had been elected President of the young nation."` The claim is
topically right and not what the question asks (the gold answer is Francisco Guterres, from the masked document): a confident answer on a plausible-but-wrong bridge.

**D. citation_gap: `2hop__144303_483189`** "What mythology is the city where Eutychides was born in a part of?" (gold: Greek mythology). The answer is correct, but the gold document `Sicyon (mythology)` is not in the context.
The claims cite `Eutychides`, `Sikyona` and `Dione (mythology)`; the last claim ("Ancient Greek mythology is associated with ancient Greece") is NLI-supported (P=0.98) yet only loosely connected to the question. The answer
is right through related evidence, not the gold chain, which is how 91 correct kb answers fail to cite a gold document. Closed-book contamination is a second route to the same outcome.

Other failure classes seen in the data: entity titles that do not exist in the corpus (the lookup falls through to a noisy search, as in `3hop1__127821_157828_239539`, where "Radio Television of Kosovo" is not a title and the gold
document is `Media in Pristina`); and empty outputs from the reasoning model (kb 2.0%, closed-book 3.3% at `max_tokens` 8000).

## 7. Cost and token accounting

- Per question (kb): 2.66 calls, 9,893 tokens (about 2,024 in the answer prompt); RRF: 1 call, 3,148 tokens; closed-book: 1 call, 1,169 tokens. The final calls behind the 8 committed main-system answer files total 16,089,089 tokens (last line of `results/summary.md`).
- The author's local call cache (`data/cache`, not committed) holds 6,511 billed calls = 11.75M prompt + 8.89M completion = 20.64M tokens for everything, including tuning and the superseded 4,000-token-cap run; 2,350 calls
  were carried over for free. Dollars depend on the provider's per-token price, which we do not assert.
- The verifier spends no LLM tokens: about 2 minutes of MPS compute for all seven systems (4,450 claims, 4,491 scored premise-claim pairs) plus a one-time ~1.4 GB model download.
- Retrieval/index build (Apple M4, 16 GB, MPS): `kb index` 123 s, `kb graph` 14 s, `kb recall` 8 s.

## 8. Limitations, stated plainly

- One run per system, one generator, 400 questions; the subset is one seeded draw.
- kb uses more tokens than the baselines (no equal-token baseline). The hop cap was tuned on a 2-question margin.
- Planned and **not run**: cross-encoder reranker, contextual chunk prefix, IRCoT-lite baseline, verifier-as-gate, hop cap 1 on the eval set.
- kb_no_graph covers 267 of 400 questions.
- The NLI verifier is an upper bound on ungrounded claims (see section 4).
- Contamination: the closed-book baseline answers 25% of questions without evidence.

## 9. Reproduce and raw outputs

```bash
python -m kb data && python -m kb ingest && python -m kb index && python -m kb graph   # once
python -m kb eval                                                                    # the one command: no network, no LLM
python -m kb eval --rerun                                                            # re-execute every LLM system first (needs LLM_* env vars)
```

`kb eval` checks the three id files against their sha256, checks every answer file covers its question set, rescoring all systems, reads the verifier caches, and writes `results/summary.json` and `results/summary.md` (identical bytes on repeat runs;
verified in a fresh clone, see README). Raw outputs: `results/answers/<system>.jsonl` (raw model text, parsed JSON, context paragraph ids, per-call token usage, hop trace), `results/verify/<system>.jsonl` (NLI scores,
keyed by claim text and cited span ids; model `lytang/MiniCheck-RoBERTa-Large` at revision `74c8919647e61ed0f71bc177d94f10930f090068`), `results/verify/audit.jsonl`, `results/retrieval/`, `results/graph/summary.json`,
`results/assembly/` (tune-split choices). Scripts: `kb/score.py` (metrics), `kb/verify.py`, `kb/assemble.py`, `kb/answer.py`, `kb/evaluate.py`. Decisions and experiment history: [OPTIONS.md](OPTIONS.md).
